# Version history — why each layer exists

Read only when a rule seems odd; each line names the run that caused it.

- **v3** — Phase 0 (the selection engine), the view library, the component inventory with the universal
  state rule, foundation additions.
- **v4** — the research plan became mandatory, with depths and a ledger.
- **v5** — after Pentland, ClickUp, Vermont and Topcon came out as one product in four hues: journeys as
  flows (0.7), signature components (0.8), the agent drawer (0.9), the expression (Step 2c), a fixed
  brand source order, a rebuilt dark theme, inspiration research, the build contract, rendering safety.
- **v5.1 / v6** — consistency and density: screens in devices at real width, one overlay system,
  spacing and density tokens, table and card limits, coded variants and style sets, chart views, the
  render check.
- **v7** — after Agthia, Vermont, American Airlines, Asian Paints and Pentland were built and inspected
  live: every app was the same layout grammar, because the file pre-drew every page and the builder
  pasted it. The deliverable became a kit, not a page set (0.6); the composition model (component
  variants, layout patterns, the seeded chooser, the UX laws); a build contract that tells the builder
  to compose.
- **v8** — after the first v7 run (Asian Paints) drew 74 screens and took about 50 minutes: at most
  five full screens, with the depth moved into component pages (anatomy, variants, a static state
  matrix with state classes, a live specimen, micro-interactions, accessibility, do and don't);
  foundations show the material properly; patterns as blueprints; every journey, the demo storyline
  included, as a flow diagram with exact wording; the guide laid out like a design-system site; S1
  only unless options are asked for; research Deep only for colours, typeface and logo; a ten-item
  checklist run once; about 4,000 words of repetition removed. Then, so the builder never has to
  choose and the output stands out: a design concept per client that shapes the signature components,
  variants and one signature interaction; variants designed per client; all choosing done in this run
  (best fit first, the seed only for ties) and handed over as `#build-plan` with lookup rules for
  unlisted pages and `data-active` tags on every specimen; a design review with a list of generic tells
  and scores for distinctiveness and finish.
- **v9.1** — after the first V9 run (Fujairah Ports Authority) rendered with three defects the render
  check did not catch or let pass: the guide's left navigation squeezed to half-height overlapping
  labels; state matrices forced wide components into narrow columns; swimlane diagrams ran past their
  column with no scroll cue. Added the rules for each (Rendering safety), a `vclipped` count to the
  render check, a short-laptop viewport, and made every flag a defect outside two-line table labels.
- **v10 (POC Studio edition)** — v9.1 adopted into the POC Studio plugin, with these edits: the
  UnifyApps stand-in logo when no client logo file exists (stop 2, and the one exception to checklist
  item 9); the builder's block named the composition contract everywhere; the example evidence line
  matches the five-screen limit; every research request states its search budget, because the
  `research` skill reads Quick, Standard and Deep as larger counts; no named reviewers in the
  hand-over questions.
- **v10.1 (POC Studio 1.26)** — approved low-fidelity wireframes come before this skill (0.0): their manifest is the
  component inventory, their frames are the layouts, nothing is proposed, the baseline is always built. Design
  systems had grown an open-ended component list; the frames close it.
- **v11 (POC Studio, components first)** — the wireframes now decide the app's purpose, every page's layout, the
  journey and the signature, so this skill focuses on the components. The manifest is the starting list, and a
  gap check walks the journey, each component's actions, the scoping document's words and what every app needs,
  adding any component the wireframes missed (marked "Added by the design system", with its reason) so the
  builder never invents one. Research question 6 now asks how real products and component libraries (Mobbin
  among them) build this app's main components; the inspiration and journey-pattern questions moved to the
  wireframes. With wireframes, the scoping document is read only for what the design system needs. Three
  screens (home with the signature, the main working page, the agent drawer open) instead of five, and a
  journey-to-component table instead of flow diagrams. The state rule adds clickable vs static, expanded,
  dragging, unread, AI-written and the rest where they apply, and every component page says which states
  apply, where it is used and what its references gave it.
- **v11.1** — after the first two v11 runs (Pentland, about 20 minutes; Kroger, about 24): both met the time
  target and added real gaps (a chase composer, a decision bar with a blocked state, a notification menu; an
  AI marker, generate progress, gate messages, a reject note, a plan card menu, an ad-week picker). Fixed: the
  Pentland run left anatomy out of 33 of 36 component pages, so the check now flags it; component research ran
  under budget on both, so 3 searches per component is a floor and the check counts reference links; a wide
  component's variants get the full width (a squeezed table); the floating agent launcher never covers
  content; numbers invented where the seed is silent are listed in the port note.
- **v11.2** — after the Kroger v11.1 run (about 35 minutes, 15 searches, anatomy on every page that needs it,
  invented numbers listed, brand colour confirmed from kroger.com): it listed 13 components as added, 5 of them
  baseline atoms (status tag, toast with undo, tooltip, banner, user menu). "Added" now means in neither the
  manifest nor the baseline, with a typical range of 3 to 8.
- **v11.3** — research that runs inside the same conversation hands its answer back and the run carries on;
  in a Kroger wireframe run the research skill's "return and stop" ended the whole run before any frame.
- **v11.4** — after the Pentland v11.3 run (36 minutes; 4 real added components; every manifest component and
  frame covered; brand from pentlandbrands.com, black with cyan): the floating agent button still covered the
  Approve button on screen 2, so the three screens now leave it out and the check flags it; time-axis markers
  replace their column heading and bar labels stay clear of the today line.

- **v12** — The team judged the first automated Pentland system "sloppy" beside the human-iterated one: 24,000 words,
  91 tables and 108,000 px, components shown alone on grey, the style as text for a company that judges products by
  eye, and the house look with Inter. The register showed three apps with a timeline of text rows as their signature.
  So: Phase D (a creative director researches and proposes three directions from three sources, checked against the
  register), the hero object pictured wherever people meet it, a showcase first, compact component pages with
  budgets, `scan.py` and Step 6b (the director judges the screenshots against `calibration.md`, at most two rounds),
  the fingerprint and `register.py`, the shape scales, and the reference material moved out of SKILL.md.
- **v12.1** — The v12 Pentland run was short and on-brand, but the team found the thinking missing: 13 variants
  where the run before had 23, 6 hover states drawn where it had 57, no gradients (the thesis allowed the accent
  only as a thin line), one view per data set and the same navigation as ever. So: "draw more, write less" — the
  word and table budgets stay, the height budget rises to 55,000 px, and a richness floor is checked (25 variants,
  hover and focus on every interactive component, a #views section with each hero data set in its views and the
  navigation options, an #expressive layer with two or more brand gradients, the signature plus five key components
  at full depth). The director proposes the expressive layer and scores richness; calibration holds the team's
  verdict on v12.
- **v12.2** — Real images became a rule: when the hero object has a picture, the run finds the client's own images
  (attached files, the client's and its brands' sites, its retail listings), matches each to the seed record and its
  variant, embeds them as WebP and records `data-source`; drawn stand-ins only when every source refuses. The v12
  Pentland run did this by its own choice; now nobody has to ask.
- **v12.3** — Reads the views that wireframes v4.10 now write as objects (name, kind, grouping) and points the
  views section at the wireframes' VIEWS sheet and payoff frame.
- **v12.4** — One way in to the agent. The skill used to tell the build to open the drawer from both the top bar
  and a floating launcher, and the apps showed two Copilot buttons. Now the app chooses one (`topbar`, `launcher` or
  `command`), records it as `app.agent_entry` and `data-agent-entry`, and `check_ds.py` fails a page with both.
- **v12.5** — Flows at component level. The team's review of the human-iterated Pentland system: it explained each job
  as a flow panel (several components working together, live, followed by three principle cards that state the UX
  decisions), between the single components and the full screens. The automated systems had only components and
  screens. A `#flows` section now carries one panel per capability, covering every journey step, and `check_ds.py`
  checks it. The flow panels take room, so the page-height budget rose from v12.1's 55,000 px to 70,000 px
  (`scan.py`).
- **v12.6** — From the v12.5 Pentland run: a missing picture is drawn as the item's silhouette (never a hatched
  box); flow components get their real width and each thing appears once per panel; `scan.py` flags text cut short
  in flow panels and `check_ds.py` flags text repeated inside a panel.
- **v12.6 (POC Studio edition)** — adopted into the POC Studio plugin with these edits: pictures of the hero object
  are HTML/CSS mockups (no fetching or embedding of photos, which took much of a run; the build seeds the real images
  from scoping §19), and the skill finds its own folder
  (`$D`) and keeps the register of apps outside the plugin cache (`$R`, `~/.local/poc-studio/design-register.json`,
  seeded from `register/register.json`) so an update never loses it; an older wireframe manifest without the v4.10
  fields falls back to the scoping document, and `check_ds.py` prints each check it cannot run as `skipped`; the
  sections now agree on the height budget (70,000 px), the variant rule (2 or 3 for every hero, interactive and
  signature component, coded by family), the radii per shape, the measured colour counts, the research depth in the
  checklist, the number of full-depth component pages (the signature plus up to five) and the six deliverables.
